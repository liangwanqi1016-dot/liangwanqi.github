# 웹프로그래밍 학습 및 제작 기록

이 프로젝트는 저의 캠퍼스 생활을 주제로 합니다. 캠퍼스 장소를 소개하는 HTML 페이지에서 시작해 CSS 디자인, JavaScript 상호작용, 브라우저 저장소, Flask 서버와 SQLite 데이터베이스를 차례로 추가했습니다. 아래는 현재 파일을 바탕으로 정리한 1~7주차의 학습 내용과 구현 과정입니다.

## 1주차 · 웹의 구조와 개발환경 이해하기

이번 주에는 웹페이지의 작동 방식과 앞으로 사용할 개발 도구를 이해하는 데 중점을 두었습니다. 브라우저, 서버, URL, HTTP 요청과 응답을 학습했습니다. 브라우저가 주소를 바탕으로 서버에 자원을 요청하고, HTML을 받은 뒤 필요한 CSS·JavaScript·이미지를 추가로 불러오는 흐름을 살펴봤습니다.

## 2주차 · HTML로 캠퍼스 장소 소개하기

### 주제 선정과 내용 정리

중앙도서관, B333 교실, 운동장을 선택해 제 캠퍼스 생활과 관련된 세 장소를 소개했습니다. 도서관은 조용히 공부하며 잠시 속도를 늦추는 공간이고, B333은 매주 수업을 듣고 프로그래밍을 배우며 친구들과 함께 노력하는 일상을 담은 공간입니다. 운동장은 축구와 학교 축제, 함께한 추억이 있는 장소입니다.

### 페이지 제작 과정

먼저 `index.html`에 제목, 사진과 짧은 설명으로 세 장소를 소개하고, 도서관·교실·운동장의 상세 페이지를 각각 만들었습니다. 상세 페이지에는 장소가 저에게 갖는 의미, 추천 활동과 사진을 넣고, Naver 지도 링크로 위치를 확인할 수 있도록 했습니다.

이어서 첫 화면과 상세 페이지를 연결하고, 상세 페이지에는 처음으로 돌아가기와 앞·뒤 장소 이동 링크를 추가해 연속해서 둘러볼 수 있도록 했습니다. 첫 화면에는 추천 방문 순서도 **B333 → 운동장 → 중앙도서관**으로 작성했습니다.

이 과정에서 HTML 문서 구조, 제목과 문단, 목록, 이미지와 링크를 주로 연습했습니다. 원본 페이지에는 사진을 직접 촬영한 것으로 표시했습니다. 구체적인 찾아가는 길, 이미지 대체 설명과 모든 링크의 실제 동작은 추가로 확인해야 합니다.

## 3주차 · CSS로 페이지 스타일 조정하기

### 내용에서 디자인으로

기존 HTML에 `styles.css`를 연결해 색상, 글꼴, 페이지 너비, 간격, 이미지 모서리와 링크 상태를 설정했습니다. 공통 스타일을 한 파일에 모아 여러 페이지를 함께 조정하기 쉽게 했습니다.

페이지마다 다른 body class를 사용했습니다. 첫 화면은 연한 파란색의 캠퍼스 분위기, 도서관은 크림색과 명조 계열 글꼴의 독서 분위기, B333은 연한 초록색의 학습과 일상 분위기, 운동장은 어두운 배경과 따뜻한 색상의 활동 분위기를 표현했습니다.

### 작은 화면에 맞추기

CSS에 `@media(max-width:768px)`를 추가해 좁은 화면에서 바깥 여백, 제목 크기와 구역 사이 간격을 줄이도록 했습니다. 이미지가 내용 영역을 넘지 않도록 너비를 제한하고, 링크의 hover와 키보드 focus 효과도 설정했습니다.

2·3주차는 같은 장소 소개 파일을 사용하므로 `week2-3`에 함께 저장했습니다. 현재 파일은 후속 기능이 추가된 통합 버전이며, 2주차의 순수 HTML 과거 버전은 아닙니다.

## 4주차 · JavaScript로 상호작용 구현하기

### 장소와 지도 전환

먼저 장소 이름, ID와 지도 검색어를 배열에 저장하고, 이 데이터를 바탕으로 선택 버튼을 만들었습니다. 버튼을 누르면 `selectPlace()`가 해당 장소 설명의 표시 상태를 바꾸고, Google 지도 iframe과 외부 지도 링크를 갱신합니다. 버튼의 `aria-pressed`는 현재 선택을 나타내며, 처음에는 도서관을 선택하도록 했습니다.

이 부분에서 배열, 객체, DOM 선택, 이벤트 리스너와 페이지 속성 변경을 연습했습니다. 현재 지도는 장소 검색 방식이므로 B333의 정확한 위치는 따로 확인해야 합니다. 첫 화면에는 세 장소의 개요와 지도 설명 구역이 함께 남아 있어 기존 필터 버튼의 기능과 전체 내용 구조도 추가 점검이 필요합니다.

### 통계 그래프

Chart.js로 장소별 방문 수 막대그래프와 월별 추이 선그래프를 만들고, 탭 버튼으로 전환하도록 했습니다. JavaScript가 항목 이름, 수치와 그래프 설정을 준비하고 Canvas에 그래프를 그립니다.

현재 수치는 코드 배열에 직접 작성되어 있고 실제 출처가 없어 그래프 시연용으로만 사용할 수 있습니다. 공개 데이터 분석을 완성하려면 공개적으로 사용할 수 있는 CSV를 선택하고, 읽기 코드와 출처 설명을 추가한 뒤 두 그래프의 해석과 한계를 각각 작성해야 합니다.

### Canvas 별 모으기 게임

Canvas에 노란 별과 빨간 함정을 그리고, 목표 위치를 무작위로 바꾸도록 했습니다. 사용자가 클릭하거나 화면을 터치하면 화면 좌표를 Canvas 좌표로 변환한 뒤 목표를 맞혔는지 판단합니다.

노란 별은 1점, 빨간 함정은 -2점이며 최저 점수는 0점입니다. 한 판은 20초이고, 12점에 도달하면 완료 메시지를 표시합니다. 시간이 끝나면 이번 결과를 보여줍니다. 코드에는 카운트다운, 초기화, 재시작과 현재 페이지 안에서의 최고 점수 표시도 포함했습니다. 좌표 계산, 조건문, 타이머와 게임 상태 관리를 연습했으며, 실제 플레이 후 한 번 이상의 개선 내용과 휴대전화 터치 결과를 기록해야 합니다.

## 5주차 · 음식 취향 테스트와 데이터 저장

### 질문과 결과 설계

자주 가는 식당, 새로운 가게, 입맛과 식사 습관 등을 주제로 8개의 양자택일 질문을 만들었습니다. 사용자가 별명을 입력하면 답변을 시작하고, 화면에 문항 번호와 진행률을 표시하며, 완료 후 결과 카드를 보여줍니다.

결과는 ‘매운맛 고인물’, ‘담백한 힐링 푸디’, ‘찐뉴 트렌드 푸디’, ‘요즘 감성 건강 푸디’의 네 유형입니다. 답변 점수를 누적해 익숙한 곳/새로운 곳과 매운맛/담백한 맛 두 축으로 결과를 정합니다. 동점이면 각각 OLD와 SPICY를 선택합니다. 현재 SLOW/FAST 답변은 네 유형의 계산에 반영되지 않아 추가 설명이나 조정이 필요합니다.

### 저장과 복원

별명, 현재 문항과 답변을 sessionStorage의 `week5.draft`에 저장했습니다. 페이지를 다시 열면 초안을 읽고 이어서 풀기 또는 초안 삭제를 제공해 같은 탭에서 새로고침한 뒤에도 진행 상황을 복원할 수 있도록 했습니다.

테스트가 끝나면 별명, 결과와 완료 시간을 localStorage의 `week5.history`에 저장하고 최대 20개를 유지합니다. 첫 화면은 저장된 데이터를 읽어 기록 목록을 만들고, 개별 기록 삭제와 전체 기록 삭제를 제공합니다. 별명 등의 내용은 `textContent`로 표시합니다.

## 6주차 · Flask로 이미지 처리와 음성 생성하기

### 이미지 처리 앱

Flask 이미지 처리 예제를 정리하고 학습했습니다. 브라우저에서 이미지, 처리 방식과 매개변수를 선택해 서버로 보내면, Flask가 입력을 읽고 검사한 뒤 OpenCV로 흑백·흐림·윤곽선 처리를 수행합니다. 결과를 PNG로 인코딩해 웹페이지로 반환합니다.

프론트엔드는 처리된 이미지와 시간 정보를 표시합니다. 이 과정을 통해 일반 form 제출과 fetch 요청의 차이, 알고리즘 계산 시간·서버 처리 시간·브라우저 왕복 시간이 각각 어떤 단계를 포함하는지 학습했습니다.

주요 파일은 `app.py`, `templates/index.html`, `static/image.js`입니다. 실행할 때는 먼저 `requirements.txt`의 의존성을 설치한 뒤 Flask를 시작합니다. 현재 소스와 실행 안내를 저장했으며, 세 가지 이미지 처리 결과, 이미지 크기와 커널에 따른 시간 비교, Render 주소와 휴대전화 업로드 화면은 추가해야 합니다.

### 서버 텍스트 음성 변환

영어 문장을 Flask에 보내면 서버의 Piper 모델이 WAV 음성을 생성합니다. 브라우저는 음성을 받은 뒤 Blob과 AudioContext로 데이터를 읽고, Canvas에 파형을 표시하며 생성 시간, 음성 길이와 파일 크기를 보여줍니다.

주요 파일은 `tts_app.py`, `templates/tts.html`, `static/tts.js`입니다. 사용 전 TTS 의존성을 설치하고 `en_US-lessac-low` 영어 모델을 내려받아야 합니다. 핵심은 서버가 실제 음성 합성을 수행하고, 브라우저는 입력과 결과 표시를 담당한다는 점입니다.

## 7주차 · Flask와 SQLite 게시판

### 로그인에서 공통 글 목록으로

‘캠퍼스 한 끼 추천’을 주제로, 학교 근처에서 추천할 만한 식사를 남기는 게시판을 구성했습니다. 먼저 가입, 로그인과 로그아웃 흐름을 학습하고, SQLite에 사용자와 글을 저장해 여러 계정이 같은 서버에서 공통 목록을 읽도록 했습니다.

글을 올릴 때 서버는 현재 로그인한 계정을 작성자로 기록합니다. 삭제할 때는 화면의 버튼 표시뿐 아니라 서버에서도 글 작성자와 현재 사용자가 같은지 확인합니다. 단순히 버튼을 숨기는 데 그치지 않고, 자신의 글만 삭제할 수 있도록 제한하는 방식입니다.

### 신고와 관리

기본 게시판에 신고, 검색, 신고된 글 필터, 관리자 삭제와 계정 차단·해제를 추가했습니다. 현재 로컬 소스에는 관리 흐름을 시험하기 위한 연습 계정과 글의 생성·정리 기능도 포함되어 있습니다.

이 프로젝트를 통해 사용자, 글과 신고 사이의 데이터 관계, 비밀번호 해시, CSRF 검사, 출력 이스케이프와 서버 권한 판단을 학습했습니다. 주요 파일은 `app.py`, `schema.sql`, `templates/`, `static/style.css`입니다.
