# 웹프로그래밍 학습 및 제작 기록

이 프로젝트는 가톨릭대학교에서의 캠퍼스 생활을 주제로 합니다. HTML로 장소를 소개하는 페이지에서 시작해 CSS 디자인, JavaScript 상호작용, 브라우저 저장소, Flask 서버와 SQLite 데이터베이스로 학습 범위를 넓혔습니다. 아래는 현재 소스 파일을 바탕으로 정리한 1~7주차의 학습 내용과 구현 과정입니다.

> 실제 실행·테스트·배포 여부를 확인하지 못한 항목은 완료한 것으로 기록하지 않았습니다.

## 1주차 · 웹의 구조와 개발환경

이번 주의 학습 내용은 웹페이지가 전달되는 과정과 개발 도구의 역할입니다. 브라우저가 URL을 바탕으로 서버에 HTTP 요청을 보내고, HTML을 받은 뒤 CSS·JavaScript·이미지를 추가로 불러오는 흐름을 살펴봅니다.

개발 과정에서는 편집기로 HTML을 작성하는 방법과 Git·GitHub의 차이, 파일 저장·commit·push의 역할을 익히는 데 초점을 둡니다. Git은 로컬 변경 이력을 기록하고, GitHub는 원격 저장소를 관리하며, GitHub Pages는 정적 웹페이지를 공개하는 데 사용합니다.

현재 폴더에는 1주차의 독립된 페이지가 남아 있지 않습니다. 첫 commit과 push, 최초 배포 과정은 실제 Git 이력과 함께 보완할 내용입니다.

## 2주차 · HTML로 캠퍼스 장소 소개하기

### 주제와 내용 구성

중앙도서관, B333 교실, 운동장을 소개할 장소로 선택했습니다. 도서관은 조용히 공부하며 잠시 속도를 늦추는 공간이고, B333은 매주 수업을 듣고 친구들과 프로그래밍을 배우는 공간입니다. 운동장은 축구와 학교 축제, 함께한 추억을 담은 장소입니다.

### 페이지 제작 과정

먼저 `index.html`에 세 장소의 제목, 사진과 짧은 소개를 배치했습니다. 이어서 장소별 상세 페이지를 만들고, 각 장소가 나에게 갖는 의미와 추천 활동을 작성했습니다. 위치를 확인할 수 있도록 Naver 지도 링크도 넣었습니다.

그다음 첫 화면과 상세 페이지를 연결하고, 상세 페이지에는 처음으로 돌아가기와 앞·뒤 장소 이동 링크를 추가했습니다. 추천 방문 순서는 **B333 → 운동장 → 중앙도서관**으로 정했습니다.

이 과정에서 HTML 문서 구조, 제목과 문단, 목록, 이미지와 링크를 연습했습니다. 원본 페이지에는 사진을 직접 촬영한 것으로 표시했습니다. 구체적인 찾아가는 길, 이미지 대체 설명과 링크 동작은 추가로 확인할 부분입니다.

## 3주차 · CSS로 페이지 꾸미기

### 내용에 스타일 적용하기

HTML로 작성한 내용에 `styles.css`를 연결해 색상, 글꼴, 페이지 너비, 간격, 이미지 모서리와 링크 상태를 설정했습니다. 여러 페이지의 스타일을 한 파일에서 관리하도록 구성했습니다.

각 페이지의 `body`에 다른 class를 사용했습니다. 첫 화면은 연한 파란색, 도서관은 크림색과 명조 계열 글꼴, B333은 연한 초록색, 운동장은 어두운 배경과 따뜻한 강조색을 사용해 장소별 분위기를 표현하고자 했습니다.

### 작은 화면에 맞추기

`@media(max-width:768px)` 규칙을 추가해 좁은 화면에서 제목 크기와 여백을 줄이도록 했습니다. 이미지가 영역을 넘지 않도록 크기를 제한하고, 링크에 hover와 키보드 focus 표시도 설정했습니다.

2·3주차는 같은 장소 소개 파일을 사용하므로 `week2-3` 폴더에 함께 정리했습니다. 현재 파일은 후속 기능이 포함된 통합 버전이며, 2주차의 순수 HTML 버전을 따로 복원한 것은 아닙니다. 원본 CSS의 일부 전역 규칙과 잘못된 속성값, 상세 페이지의 viewport 설정은 수정·점검이 필요합니다. 실제 휴대전화 화면도 확인해야 합니다.

## 4주차 · JavaScript로 상호작용 만들기

### 장소와 지도 전환

장소 이름, ID와 지도 검색어를 배열에 저장하고, 이를 바탕으로 선택 버튼을 생성했습니다. 버튼을 누르면 `selectPlace()`가 해당 장소 설명을 표시하고 Google 지도 iframe과 외부 지도 링크를 함께 변경합니다. 버튼의 `aria-pressed`로 선택 상태를 나타내며, 처음에는 도서관을 선택하도록 했습니다.

배열과 객체, DOM 선택, 이벤트 처리와 속성 변경을 연습한 부분입니다. 현재는 검색 기반 지도이므로 B333의 정확한 위치는 따로 확인해야 합니다. 첫 화면에 장소 개요와 지도 설명 구역이 함께 남아 있어 내용 구성을 점검해야 하며, 기존 필터 버튼의 동작도 확인할 필요가 있습니다.

### 통계 그래프

Chart.js로 장소별 방문 수 막대그래프와 월별 추이 선그래프를 만들고, 탭 버튼으로 전환하도록 구성했습니다. JavaScript에서 항목 이름과 수치, 그래프 설정을 준비해 Canvas에 표시합니다.

현재 수치는 코드 배열에 직접 작성된 예시 데이터이며 실제 출처가 없습니다. 공개 데이터 분석 과제로 완성하려면 CSV 읽기, 출처 표시, 그래프별 해석과 한계를 추가해야 합니다.

### Canvas 별 모으기 게임

Canvas에 노란 별과 빨간 함정을 그리고, 목표의 위치를 무작위로 바꾸도록 했습니다. 클릭이나 터치가 발생하면 화면 좌표를 Canvas 좌표로 변환한 뒤 목표에 닿았는지 판단합니다.

노란 별은 1점, 빨간 함정은 -2점이며 점수는 0점 아래로 내려가지 않습니다. 제한 시간은 20초이고, 12점에 도달하면 성공 메시지를 표시합니다. 시간 종료, 초기화, 재시작과 현재 페이지 안에서의 최고 점수 표시도 포함했습니다. 좌표 계산, 조건문, 타이머와 게임 상태 관리를 연습했으며, 실제 플레이 후 개선한 내용과 휴대전화 조작 결과는 추가 기록이 필요합니다.

## 5주차 · 음식 취향 테스트와 브라우저 저장소

### 질문과 결과 구성

음식과 식사 습관에 관한 8개의 양자택일 질문을 작성했습니다. 별명을 입력하면 문제를 차례로 풀고, 진행률과 현재 문항을 확인한 뒤 결과 카드를 볼 수 있도록 시작·문제·결과 화면을 나눴습니다.

결과는 ‘매운맛 고인물’, ‘담백한 힐링 푸디’, ‘찐뉴 트렌드 푸디’, ‘요즘 감성 건강 푸디’의 네 유형입니다. 익숙한 곳/새로운 곳과 매운맛/담백한 맛 점수를 합산하며, 동점이면 각각 OLD와 SPICY를 선택합니다. 현재 SLOW/FAST 선택은 네 유형의 분류에 반영되지 않으므로 규칙을 설명하거나 조정할 필요가 있습니다.

### 저장과 복원

별명, 현재 문항과 답변을 sessionStorage의 `week5.draft`에 저장합니다. 저장된 초안이 있으면 이어서 풀거나 초안을 삭제할 수 있도록 했습니다.

완료 후에는 별명, 결과와 시간을 localStorage의 `week5.history`에 저장하고 최근 20개를 유지합니다. 저장된 기록을 읽어 목록을 만들고, 기록 하나 삭제와 전체 기록 삭제 기능을 제공합니다. 별명 등은 `textContent`로 표시합니다.

이 과정에서 **읽기 → 상태 변경 → 저장 → 화면 갱신**의 흐름을 익혔습니다. 현재 완료 기록에는 문항별 답변이 없어 두 기록 비교는 지원하지 않습니다. 저장 데이터 보기, 초안 검증과 저장 실패 처리도 보완해야 합니다. 새로고침·독립적인 새 탭·탭 닫기·삭제 후 재방문 결과는 실제로 확인해 기록할 예정입니다.

## 6주차 · Flask로 이미지 처리와 음성 합성하기

### 이미지 처리 앱

Flask 이미지 처리 예제를 정리하고 브라우저와 서버의 역할을 살펴봤습니다. 브라우저는 이미지와 처리 옵션을 보내고, Flask는 입력을 검사한 뒤 OpenCV로 흑백·흐림·윤곽선 처리를 수행합니다. 결과를 PNG로 변환해 반환하면 브라우저가 이미지와 시간 정보를 표시합니다.

일반 form 제출과 fetch 요청의 차이, 알고리즘 계산 시간·서버 처리 시간·왕복 시간의 범위를 배우는 실습입니다. 주요 파일은 `app.py`, `templates/index.html`, `static/image.js`입니다. 실행 시 `requirements.txt`의 패키지를 설치하고 Flask 서버를 시작합니다.

현재 소스와 실행 안내가 준비되어 있습니다. 세 처리 결과, 이미지 크기와 커널에 따른 시간 비교, Render 주소와 휴대전화 업로드 화면은 추가로 확인·기록해야 합니다.

### 서버 TTS

영어 문장을 Flask에 보내면 서버의 Piper 모델이 WAV를 생성하는 구조입니다. 브라우저는 Blob과 AudioContext로 응답을 읽고, Canvas에 파형을 그리며 생성 시간·음성 길이·파일 크기를 표시합니다.

주요 파일은 `tts_app.py`, `templates/tts.html`, `static/tts.js`입니다. TTS 패키지를 설치하고 `en_US-lessac-low` 영어 모델을 내려받아 실행합니다. 핵심은 서버가 실제 음성을 만들고 브라우저가 입력과 결과 표시를 담당한다는 점입니다.

현재 파일은 주로 수업 예제입니다. 자신의 사용 상황에 맞는 요소를 추가하고, 서로 다른 영어 문장 두 개의 파형과 결과 화면을 기록해야 합니다. 이 실습은 로컬 실행을 기준으로 하며 별도 배포는 필요하지 않습니다.

## 7주차 · Flask와 SQLite로 로그인 게시판 만들기

### 로그인과 공통 글 목록

‘캠퍼스 한 끼 추천’을 주제로 학교 근처에서 추천하고 싶은 식사를 남기는 게시판을 구성했습니다. 가입·로그인·로그아웃에서 시작해 SQLite에 사용자와 글을 저장하고, 여러 계정이 같은 서버의 글 목록을 읽도록 확장했습니다.

글 작성 시 로그인한 사용자 번호를 작성자로 기록합니다. 삭제할 때는 화면의 버튼 표시뿐 아니라 서버에서도 작성자와 현재 사용자가 같은지 확인해 자신의 글만 삭제할 수 있도록 합니다.

### 신고와 관리 기능

기본 게시판에 신고, 내용 검색, 신고된 글 필터, 관리자 삭제와 계정 차단·해제를 추가한 구조입니다. 현재 로컬 소스에는 관리 기능을 시험하기 위한 연습 계정·글 생성과 정리 기능도 있습니다.

사용자·글·신고의 관계와 함께 비밀번호 해시, CSRF 확인, 출력 이스케이프와 서버 권한 검사를 학습했습니다. 주요 파일은 `app.py`, `schema.sql`, `templates/`, `static/style.css`입니다.

로컬 실행에는 패키지 설치, 무작위 SECRET_KEY 설정과 DB 초기화가 필요합니다. 기존 README에는 Render 주소가 있지만 이번 정리에서는 온라인 로그인과 관리 기능을 다시 검증하지 않았습니다. 기존 저장소와 정리 폴더의 7주차 소스도 서로 달라 배포 버전을 확인해야 합니다. 관리자 ID와 비밀번호는 사이버캠퍼스 제출란에만 적고 공개 README에는 넣지 않습니다.

## 파일 구성과 실행

```text
网页/
├── week2-3/    # HTML 캠퍼스 소개와 CSS
├── week4/      # 지도 전환, 통계 그래프, Canvas 게임
├── week5/      # 음식 취향 테스트와 브라우저 저장소
├── week6/      # Flask 이미지 처리와 서버 TTS
└── week7/      # 로그인 게시판과 관리 기능
```

- 2·3주차: `week2-3/index.html`
- 4주차: `week4/index.html`, `map.html`, `statistics.html`, `game.html`
- 5주차: `week5/food.html`
- 6·7주차: 각 폴더의 README에 따라 Python 서버를 실행합니다. `templates`의 HTML을 직접 여는 방식으로는 동작하지 않습니다.

주차별로 필요한 이미지·CSS·JavaScript를 함께 배치해 기존 상대 경로를 유지했습니다. 이번 파일 정리에서는 원본 웹페이지 내용을 변경하지 않았습니다. 1주차의 독립 파일은 없으며, 2·3주차 공통 파일은 하나의 폴더로 합쳤습니다.

이번 작업에서는 AI를 활용해 수업 요구사항과 파일 구조를 정리하고, 2·3주차 폴더 병합, 정리 폴더 업로드와 README 작성을 진행했습니다. 원래 웹페이지 제작 과정에서 Copilot 등을 사용했다면 실제 대표 질문, 직접 수정한 코드와 실행·검증 과정을 추가로 기록할 수 있습니다.
